# CABA NIGHT 页面规划

## 1. 本期定位与范围

本期 Web 是店铺、Cast（キャスト）和 Plan（店铺方案）的信息展示与联系平台，支持桌面和手机浏览器。用户浏览信息后，通过电话、LINE、商家官网或 Cast 公开社媒自行联系。手机浏览器沿用本期范围，不单独加入交易功能。

用户已明确：暂不接支付，提供店铺、Cast、Plan、联系商家和 Cast 社媒。本文在此基础上补充搜索、地区浏览、收藏、活动资讯、信息纠错等能力。路由为建议，尚未实现。

本期建议同时暂不建立站内预约、订单、退款及积分账户；咨询、预约时间、最终费用等由用户与商家直接确认。站内咨询表单、在线聊天和用户账号不作为首版前置条件。以后如需站内预约，可单独增加需求。

| 项目 | 当前状态 |
| --- | --- |
| Home 桌面 / 移动端参考设计 | 原还原稿已保留；新版 PC 首页已按信息展示与联系方向调整 |
| Vue 工程 | 已创建，只有品牌基础入口 |
| PC 页面设计 | 已完成 26 张页面及状态、联系交互画板，见 [PC 设计索引](pc-design-index.md)；条款正文和真实资料待提供 |
| Home Vue 页面及其他页面 | 待开发；其他移动端页面待设计 |

优先级：

- **P0：首版核心。** 地区与搜索 → 店铺 / Cast / Plan 详情 → 联系商家 / 打开公开社媒；以及基础帮助、信息纠错和系统状态。
- **P1：内容与留存。** 本地收藏、活动、优惠信息、专题、规则透明的榜单。
- **后续评估。** 用户账号、云端收藏、评价投稿、消息中心、站内咨询和站内预约；支付、订单、退款、积分另外立项。

## 2. 建议站点结构

```text
Home
├── 地区选择 → 地区介绍 → 店铺 / Cast / Plan 列表
├── 店铺搜索 → 店铺详情
│   ├── 店铺相册 / 设施 / 交通 / 常见问题
│   ├── 所属 Cast → Cast 详情 → 公开社媒
│   ├── 店铺 Plan → Plan 详情 → 联系商家咨询此 Plan
│   └── 电话 / LINE / 官网 / 商家社媒 / 地图导航
├── Cast 列表 → Cast 详情 → 社媒 / 所属店铺
├── Plan 列表 → Plan 详情 → 所属店铺 / 联系商家
├── 活动 / 优惠 / 专题（P1）
├── 我的收藏（P1，本地保存）
└── 指南 / FAQ / 平台联系 / 信息纠错 / 关于 / 条款与隐私
```

首版导航建议：**エリア、店舗、キャスト、プラン、ご利用ガイド**。活动与收藏在功能完成后加入。桌面用顶栏，移动端用菜单抽屉；详情页在移动端提供底部联系栏。

## 3. P0 页面清单

| 页面 | 建议路由 | 页面内容与主要操作 |
| --- | --- | --- |
| Home | `/` | 品牌首屏、关键词与地区搜索、热门地区、精选店铺、Cast 和 Plan 入口、使用指南；内容推荐标明依据 |

| 店铺列表 / 搜索 | `/shops` | 地区、店名 / 关键词、店铺类型、参考费用、设施、支持语言等筛选；排序、分页、当前筛选条件和清空筛选 |
| 店铺详情 | `/shops/:shopId` | 基本信息、相册、介绍、费用、设施、营业时间、交通、Cast、Plan、商家联系方式、来源与更新时间 |
| Cast 列表 | `/casts` | 照片、展示名、所属店铺、地区、公开标签；按地区、店铺、姓名和已维护的语言字段筛选 |
| Cast 详情 | `/casts/:castId` | 公开资料、相册、简介、语言、公开社媒、所属店铺和联系店铺入口；不默认提供 Cast 私人联系方式 |
| Plan 列表 | `/plans` | 方案名称、店铺、地区、参考费用、时长、适用条件；按地区、店铺、方案类型、参考费用筛选 |
| Plan 详情 | `/shops/:shopId/plans/:planId` | 方案介绍、包含 / 不含项目、参考费用、税费说明、时长、人数条件、适用日期、关联店铺及咨询入口 |
| 使用指南 | `/guide` | 如何找店、查看 Cast / Plan、联系商家、查看交通；说明平台信息服务范围及直接联系流程 |
| 常见问题 | `/help` | 费用如何理解、如何联系、社媒打不开、信息更新、收藏使用、信息纠错；店铺特有问题放在店铺详情 |
| 联系平台 | `/contact` | 平台公开联系渠道、商家入驻 / 信息修改入口；与联系商家明确区分；首版可提供邮箱等实际可用渠道 |
| 信息纠错 / 举报 | `/report?type=shop&id=xxx` | 店铺 / Cast / Plan 上下文，错误联系方式、价格过时、资料错误、图片问题、失效链接等分类；首版复用平台联系渠道并提供可复制的信息模板 |
| 关于平台 | `/about` | 平台介绍、掲載范围、资料来源与审核说明；仅描述实际执行的审核和更新机制 |
| 使用条款 | `/legal/terms` | 信息服务范围、外部链接、用户使用规则等；正式内容由业务确认 |
| 隐私政策 | `/legal/privacy` | 实际使用的存储、联系信息、统计服务等说明；正式内容由业务确认 |
| 404 / 内容不存在 | `/:pathMatch(.*)*` | 返回搜索 / 首页；实体不存在与内容下架也要有对应展示状态 |

独立业务模板可复用：地区列表与介绍、三种实体列表、三种实体详情、指南 / 静态内容、联系 / 纠错、系统状态。不需要给每个店铺或 Cast 单独开发页面。

搜索条件保存在 URL，例如 `/shops?area=shinjuku&q=luxe&type=cabaret`，便于分享、刷新及返回时恢复。日期、人数若不能用于可靠的信息筛选，首版从 Home 搜索中移除，避免暗示实时可订。

## 4. 三类核心详情的字段

### 店铺 Shop

- 标识与分类：稳定 ID、店名、地区 / 商圈、店铺类型、简介、封面与相册。
- 到店信息：地址、附近车站、步行说明、地图位置、营业时间、休息日、营业日跨午夜的说明。
- 费用与设施：参考费用 / 起价、计费时长、税与服务费是否包含、包厢、可接受支付方式、吸烟等已核实设施。
- 内容关联：所属 Cast、店铺 Plan、活动与优惠信息（P1）。
- 联系方式：店铺电话、LINE、官网、商家公开社媒、支持联系的语言、建议联系时间。
- 可信度：资料来源、最后更新日期、已核实字段、纠错入口。没有信息时显示未提供，不能填成“无”。

这里的“店铺可接受支付方式”只是到店消费信息，不代表平台提供支付。

### Cast

- 稳定 ID、公开展示名、头像 / 封面、相册、简介、所属店铺、地区、公开语言和标签。
- 社媒字段按平台分别保存：Instagram、X、TikTok、公开 LINE 等；只显示 Cast / 商家授权公开的账号。
- 明确区分“Cast 官方公开账号”和“所属店铺账号”，显示平台图标、账号名及打开入口。
- 社媒为空时不渲染空按钮，提供“查看所属店铺 / 联系店铺”；链接失效可反馈。
- 出勤日期仅在有商家维护来源时显示，标注更新时间；首版不展示未经维护的“在线”“今晚出勤”或可指名保证。
- 年龄、身高等可选个人字段仅在有公开资料且确有展示需求时增加；不采集私人住址、私人手机号等信息。

### Plan

- 稳定 ID、所属店铺、名称、类型、封面、说明、适用对象与使用条件。
- 参考价格、币种、计费单位、时长、人数限制、包含与不含内容、附加费用说明。
- 适用日期 / 时间、有效期、由商家说明的使用方式；没有维护来源时不展示实时库存。
- 可展示普通、首次来店、VIP / 包厢、团体等分类；只开放实际有内容的分类。
- 主操作为“联系店铺咨询此方案”，附带店铺名、Plan 名称 / 链接；可以复制咨询文案，仍由用户自行发送。
- 已结束或下架时移除咨询此方案的主操作，提供有效 Plan 或店铺入口。

## 5. 联系与社媒交互

联系商家和打开 Cast 社媒使用详情页内区块 / 弹层，不额外增加必经页面，不要求登录。

| 渠道 | 建议交互 | 缺失 / 异常处理 |
| --- | --- | --- |
| 店铺电话 | 移动端使用电话链接；桌面显示号码并可复制 | 未提供则隐藏；无法发起呼叫时仍可复制号码 |
| 店铺 LINE | 打开商家维护的官方链接；桌面可展示对应二维码及复制链接 | 没有二维码时不放占位码；不可用时提供电话 / 官网等其他渠道 |
| 商家官网 | 明确标识外部网站，在新标签页打开 | 缺少地址不显示按钮，提供失效链接反馈 |
| Cast / 商家社媒 | 显示平台和公开账号，打开原平台，支持复制链接 | 未提供则隐藏；不把打开链接描述为联系成功 |
| 地图导航 | 展示地址、附近车站；复制地址并打开外部地图 | 无精确坐标时只显示已确认地址，不编造地图点位 |
| Plan 咨询 | 选择商家渠道，提供含店铺、Plan、详情链接的可复制文本 | 不默认向外部应用传递用户资料，也不自动发送消息 |

Plan 咨询文案示例：`您好，我想咨询「{店铺名}」的「{Plan名}」，详情：{链接}。请问适用条件和费用是什么？`

按钮文案采用“联系店铺 / 电话咨询 / LINEで問い合わせ / 查看官网 / Instagram / 复制方案信息”。外链点击只记录为访问动作，不能视为预约、到店或成交。

## 8. 共用组件与内容状态

- 导航、移动菜单、页脚、面包屑、语言选择、分页、实体卡片、地区选择、搜索和筛选面板。
- 相册预览、设施标签、参考费用明细、营业时间、地图 / 地址、外部联系区块、社媒列表、分享 / 复制链接。
- 列表空态、无搜索结果、加载与重试、404、信息不完整、内容下架、店铺停业、Cast 离店、Plan 过期、外链失效提示与反馈。
- 收藏的失效条目仍可识别和移除；Cast 换店后关联以最新公开资料为准，离店且无新店信息时不继续指向旧店咨询。
- 资料未更新不能推断为营业中 / 有空席；“营业中”仅在营业规则和当地时间可靠时展示。
- 卡片之间的费用统一显示币种、计费单位和“起 / 参考”含义；未提供价格时写“请联系店铺确认”，不以 0 元代替。
- 详情页提供稳定链接、页面标题、摘要、分享图；地区与实体详情应能被搜索引擎发现，是否增加预渲染在实现时评估。
- 所有页面适配桌面与手机浏览器，保证底部联系栏不遮挡内容，按钮有清晰标签，筛选和弹层可使用键盘操作。

语言建议先完成日语，再按实际内容供应增加中文、英语、韩语。只有已完成的语言才开放切换；店名、展示名及社媒账号保留原文。多语言范围是建议，未确认前不承诺四种语言全部上线。

## 9. 内容维护与后台建议

首版可以从结构化本地数据或现有接口读取，不要求先建完整后台。数据结构应为 Shop、Cast、Plan、Area 分配稳定 ID，通过 ID 关联；联系方式与社媒独立为可选字段，便于后续接入接口。

| 内容管理范围 | 建议能力 |
| --- | --- |
| 店铺 | 资料、相册、地区、设施、营业时间、联系方式、来源与更新时间、掲載 / 下架状态 |
| Cast | 公开资料、照片、所属店铺、社媒、在籍 / 离店状态；图片和账号展示授权信息 |
| Plan | 关联店铺、费用结构、条件、有效期、掲載 / 下架状态 |
| 内容运营 | 活动、优惠、专题、推荐位置、多语言内容、纠错处理 |
| 后续商家自助 | 商家登录、资料修改、Cast 与 Plan 维护、提交审核；是否自建待确认 |

本期后台范围不包含订单、支付、退款、结算和积分流水。推荐数据、营业信息和公开社媒需要有明确维护来源，不能从设计图样例直接当作真实数据发布。

## 10. 设计与开发顺序

1. **调整 Home 设计：** 按第 7 节替换交易入口，确认导航和联系主操作。
2. **补齐核心设计：** 店铺列表 / 详情、Cast 列表 / 详情、Plan 列表 / 详情，制作桌面和移动版；地区、指南和联系页面复用通用布局。
3. **实现 P0：** 建立 Vue 路由、样式与数据层，完成 Home → 搜索 / 列表 → 三类详情 → 外部联系 / 社媒；补帮助、政策页面和异常状态。
4. **补 P1：** 本地收藏、活动、优惠、专题、榜单及入驻介绍；有实际内容再开放入口。
5. **验收：** 核对详情关联、费用单位、联系方式、外链、信息来源、移动端操作、分享链接、返回时筛选恢复、空态及下架状态。

首版完成标准：用户不登录即可找到店铺、Cast 和 Plan，理解参考费用与条件，并顺利打开正确商家渠道或 Cast 公开社媒；全站不出现暗示已完成站内预约或支付的结果。

## 11. 后续需要落实的信息

以下不阻塞页面结构设计，可先按本文方案推进：

- 首批地区、店铺类型、真实店铺 / Cast / Plan 数据及图片由谁提供，谁负责更新？
