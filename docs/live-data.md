# Web 动态数据接入

Web 通过 CABA NIGHT 后台的公开 API 读取店铺、Cast、套餐。没有管理账号、Token 或支付请求。

## 接口及页面

| 接口 | 用途 |
| --- | --- |
| `GET /api/cabakura_home/index?strict_search=1&area_tree=1` | 店铺、Cast、地区和店铺已登记的套餐集合 |
| `GET /api/cabakura_home/detail?shop_id={id}` | 店铺详情、旗下 Cast、套餐完整条件 |

首页、店铺/Cast/套餐列表及详情页、地区页、推荐店铺和收藏页使用真实记录。其他资讯、指南等页面仍使用原有设计内容，未接入资讯模块。

- 店铺路由：`/shops/20`；Cast：`/casts/19`；套餐：`/shops/20/plans/20-0`。
- 套餐键沿用后台规则 `{shop_id}-{package_index}`，校验套餐所属店铺；删除或调整套餐顺序可能改变旧链接的对应项。后台暂无稳定套餐 ID。
- 展示店铺集合内全部非 `private` 套餐，不受预约开关、推荐开关和首页推荐套餐数量上限约束。只展示信息，不创建订单、不预约、不支付。
- 金额、描述、人数、有效期、优惠条件来自后台；没有登记时不补造 60 分钟等条件。过期套餐标注“掲載期間終了”，不把已过期折扣当作当前价格。
- 图片统一补全为 API 域名的完整 HTTP(S) 地址，兼容完整 URL、`/uploads/...`、`uploads/...`。
- 打开页面或切换目录/详情路径时重新请求；查询参数筛选在当前返回的数据内完成。后台保存后刷新 Web 页面即可更新。
- 关键词、地区、店铺、参考费用、类型筛选使用真实字段；服务设施只匹配后台已登记的相应标签。无匹配时显示空结果。
- 收藏仅在本浏览器保存真实记录 ID，不需要登录。已删除、设为私有或无法通过接口获取的项目不显示为设计示例。
- 请求超时/失败显示重试入口，不使用设计样本冒充接口结果。不存在的详情返回 404 页面。

## 配置与部署

复制 `.env.example` 为 `.env.local` 可以调整 `VITE_API_ORIGIN`。默认连接现有 HTTPS 后台。变量会在构建时公开，不能填写管理凭证。

```sh
npm run dev
npm run build
npm run preview
```

部署时静态站点需配置 history fallback 到 `index.html`，并确保 API 允许正式 Web 域名的 CORS 请求。开发浏览器已验证 `localhost:5174` 可直接跨域读取。

## 现有公开接口的边界

- 目前店铺电话、邮箱、LINE/官网和 Cast 社媒 URL 未在这两个公开接口中返回。Web 会显示未登记；以后需要后台公开字段后才能提供对应联系入口。Web 不会读取管理接口来绕过此限制。
- 当前列表接口限制最多 50 家店铺、200 位 Cast。当前后台的 10 家店铺、20 位 Cast 均已覆盖；超出上限时，需要后台新增分页接口以提供完整目录。
- 套餐详情中的原始字典值 `option_*` 不作为用户标签显示；已公开的文字标签和套餐名称正常展示。

## 地区树接入（2026-11-09）

- 地区目录、首页搜索和店铺/Cast/套餐的地区筛选共用公开接口的 `area_tree`，保留后台排序及都道府县、市区、下级地区的层级和 ID。
- 地区目录的都道府县切换按钮从树的根节点动态生成。地区 ID 用于路由及查询参数，不再用设计稿中的固定城市列表作为选项。
- 地区详情和筛选通过接口的 `area` 参数获取实际归属的店铺/Cast ID，再与目录数据关联；后台现有接口接收地区名称，前端会将 ID 转为后台登记的名称，不直接把数字 ID 发送给名称筛选接口。
- 公开接口只返回后台允许展示、且关联公开店铺的地区。新增/改名/调整层级后，刷新 Web 页面读取最新结果；没有公开店铺的地区不会自动出现在目录中。
- 验证：东京及大阪都道府县各 5 家店铺；大阪 Cast 10 位；港区套餐 2 个；地区目录东京 3 个市区、大阪 1 个市区；首页选择大阪提交得到 5 家店铺；375px 地区目录与详情无横向溢出。
